# ChipDue project instructions

- When work changes or builds this project, push the verified result and deploy it to production by default unless the user explicitly asks not to deploy. Verify the live deployment before reporting completion.
- Use a live-first information hierarchy throughout the product: show current, time-sensitive, actionable data and recent activity before stable reference material. Put static rules, educational copy, catalogs, and configuration details below the live content they support unless that context is required to act safely or interpret the live state.
- Deploy production through a push to GitHub and Vercel's Git integration. Do not use a direct Vercel CLI deploy.
