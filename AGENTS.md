# ChipDue project instructions

- When work changes or builds this project, push the verified result and deploy it to production by default unless the user explicitly asks not to deploy. Verify the live deployment before reporting completion.
- Use a live-first information hierarchy throughout the product: show current, time-sensitive, actionable data and recent activity before stable reference material. Put static rules, educational copy, catalogs, and configuration details below the live content they support unless that context is required to act safely or interpret the live state.
- Prioritize important, current dynamic information at the top of each page. Put future planning, setup prompts, and sections without actionable data below current progress and deadlines. On Bonuses, show the bonus pipeline before repeat-bonus eligibility tracking.
- Automate first: use connected accounts, transaction history, saved records, and verified rules to collect data, match offers, calculate progress, and update tracking automatically. Manual logging is a fallback for unavailable data or corrections, not the default workflow. Check available sources before asking for input, and clearly distinguish uncertain inferences from confirmed facts. Preserve accepted offer terms and explicit user corrections when refreshing data.
- Deploy production through a push to GitHub and Vercel's Git integration. Do not use a direct Vercel CLI deploy.
